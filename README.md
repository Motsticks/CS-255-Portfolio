# CS-255-Portfolio

## CS 255 System Analysis and Design Portfolio

### DriverPass Project Summary

The DriverPass project involved designing a system for a client who wanted to help students prepare for their driving tests. The proposed system would allow students to register for accounts, browse driving lesson packages, schedule or change driving lessons, access online lessons and practice tests, and view their progress. The system would also support administrative functions, including managing customer information, managing lesson reservations, generating reports, and maintaining system access.

### What I Did Particularly Well

I believe I did particularly well at identifying the main users of the DriverPass system and organizing the system requirements around their needs. I identified different roles, including students, the secretary, the owner, and the IT officer, and considered what each role needed to accomplish. I also used UML diagrams to represent the system's structure and relationships, helping me visualize how the different parts of the system would work together.

### What I Would Revise

If I could revise one part of my work, I would spend more time reviewing my UML diagrams and making sure the relationships between system components were clear and consistent. I would also compare the diagrams against the requirements to confirm that every important customer need was represented. Improving the organization and clarity of the documentation would make it easier for developers to understand the design and implement the system correctly.

### Interpreting and Implementing User Needs

I approached the DriverPass project by considering what the client wanted the system to accomplish and identifying the features needed to support those goals. For example, students needed a way to schedule lessons and access practice materials, while administrative users needed tools to manage reservations, customer information, and reports. These needs influenced the system requirements and design decisions. Considering user needs is important because software must solve problems for the people who will use it. If the design does not meet those needs, the system may be difficult to use or fail to provide the intended value.

### My Approach to Software Design

My approach to software design is to start by understanding the problem, identifying stakeholders, and gathering requirements before deciding how the system should work. I would then identify the system's users, define their responsibilities, and use tools such as use case diagrams, activity diagrams, sequence diagrams, and class diagrams to represent different aspects of the design. In future projects, I would also review the requirements and diagrams together, ask for feedback, and revise the design before implementation. These strategies help reduce misunderstandings, improve communication among team members, and create software that better meets user expectations.
